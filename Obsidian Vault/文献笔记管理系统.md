高效地搭建一个文献-笔记管理系统

# 软件选择

## 工作流

把整个工作流分成三层，使用两个软件：

```text
Zotero：文献层（文献+标注+引用）
- 元数据
- PDF
- 标注
- citekey
- 引用导出
- 阅读状态标签

Obsidian：笔记层
- 每篇文献一篇 literature note
- 问题导向的文献目录
- 方法 / 数据集 / 概念 / 争议的主题笔记
- 论文项目笔记

AI / Codex：助手层
- PDF 转 md 后喂给 AI
- 批量总结、对比、抽取表格
- 写脚本自动生成 AI context pack
- 绝不作为事实源或主笔记库
```

Zotero 最擅长管理文献对象、附件、引用和标注；Obsidian 最擅长长期知识组织和双链；AI 最擅长临时加工、抽取、重组和批处理。

```
浏览器上发现论文
  ↓
Zotero Connector 保存到 Zotero
  ↓
Zotero 负责 metadata / PDF / citekey / tags / collection / annotation
  ↓
读 PDF，做标注
  ↓
把标注或核心理解转成 Obsidian 的 @citekey.md literature note
  ↓
文献 note 链接到 Concepts / Methods / Datasets / Maps
  ↓
Maps 逐渐形成研究问题
  ↓
进入 50_Projects/
  ↓
AI 只处理临时 context pack、对比表、提取、草稿辅助
```

## 组织方式

obsidian是完全本地化的软件，obsidian的仓库（可以认为是笔记本、资料库）其实就是本地的文件夹，所以建立一个obsidian仓库作为笔记文件夹。同理，这也是codex里打开的项目。

但Zotero是一个本地优先的文献数据库应用，有自己独立的数据存储区（data directory文库）。

```
Zotero Data Directory/
├── zotero.sqlite        # 最重要：Zotero 数据库
├── storage/             # PDF、网页快照、附件
├── styles/
├── translators/
└── 其他配置文件
```

因而我们可以考虑两份文件夹，一份是笔记文件夹，使用obsidian和codex打开、编辑；一份是Zotero自行管理的文库，该文库可以通过软件自动同步。**不要把文献源文件存放到笔记文件夹里**。

```
Zotero：真实文献库
- 元数据
- PDF
- tags
- ……

Obsidian：知识库 / 笔记库
- @citekey.md 文献笔记
- 主题笔记
- ……
```



# Zotero介绍

Zotero是文献数据库 + PDF 附件管理器 + 阅读标注器 + 引用生成器

[Zotero安装和配置](https://zhuanlan.zhihu.com/p/1909950881870362046)，这篇知乎的文章写得很清晰

## Zotero里的文献

一篇文献、一个网页或者一章书，在zotero里是一个Item，Item存储在Data Directory的Storage文件夹里，包含文献的本体和很多附加内容：

```
一个 Zotero 条目 Item
├── 元数据 metadata
│   ├── 标题
│   ├── 作者
│   ├── 年份
│   ├── 期刊 / 会议
│   ├── DOI / arXiv / ISBN
│   └── URL
│
├── 附件 attachments
│   ├── PDF
│   ├── 网页快照
│   └── 补充材料
│
├── 标注 annotations
│   ├── 高亮
│   ├── 下划线
│   ├── 批注
│   └── 区域截图
│
├── 笔记 notes
├── 标签 tags
├── 所属集合 collections
└── citation key / 引用信息
```

注意，storage/ 下面的文件夹名字（Item）通常不是我们能读懂的论文名，这会为我们将PDF单独迁移出Zotero带来困难……


## 获取文献

### Connrctor

Zotero官方推荐必装浏览器插件zotero connector，Connetor让我们可以直接将浏览器上看到的论文保存到zotero，还会识别网页中的 bibliographic information，并一键添加

同时，Zotero 会根据父条目的 bibliographic data 自动重命名附件文件，方便在系统搜索里找到 PDF

保存论文时，尽量在论文详情页点击 Connector，而不是在 PDF 页面点击。这样方便获取更多信息。

### DOI / ISBN / PMID

Zotero 顶部有一个类似魔法棒的按钮，在里面输入DOI / ISBN / PMID / arXiv ID等，软件会自动查 metadata 并创建条目

### 下载后拖拽

把一个 PDF 文件直接拖进 Zotero，软件会尝试自动解析元数据，但不一定完全准确（尤其是扫描版）

### 数据库批量导入

部分数据库支持导出`.bib`、`.ris`等格式的文件，将其import到zotero，软件会尝试自动获取文献


## 同步机制

Zotero的同步有两种机制，如果不使用额外的云同步或者开会员，建议就用Data sync
```
Data sync：同步文献条目、元数据、标签、笔记、全文索引等
File sync：同步 PDF、网页快照、图片、附件等文件
```

不要把 Zotero data directory 放在 Dropbox、Google Drive、OneDrive 等云同步文件夹里，不过可以定期备份整个文件夹（备份时关闭zotero，避免数据库正在写入）

## 阅读文献

使用zotero管理文献也意味着在这个软件里阅读文献，常用的功能有：

```
Highlight：高亮
Underline：下划线
Note：写批注
Area annotation：框选图表或公式区域
Tags / colors：用颜色区分用途
```

高亮的颜色应该自成系统，不要随便标，比如

```
黄色：核心观点 / main claim
蓝色：方法 / model / algorithm
绿色：实验设置 / dataset / metric
紫色：结果 / finding
红色：问题 / limitation / 可攻击点
灰色：背景知识
```

从 Zotero 6 开始，Zotero 把 annotations 存在 Zotero 数据库里，而不是直接写入 PDF 文件。因此直接复制PDF分享出去的是无标注版本，除非用 Zotero 的导出 / 保存副本功能

## 插件安装

Zotero 插件通常是 .xpi 文件。下载 .xpi 到电脑，然后在 Zotero 中点击 Tools → Plugins，并把 .xpi 拖到 Plugins 窗口即可安装。

[中文插件市场](https://zotero-chinese.com/en/plugins/)，可以在这里安装

推荐的插件：
- Add-on
	- 安装后，可以在Zotero内部安装插件，无须打开网页
- Better BibTeX
	- 稳定 citation key
	- 自动导出 .bib
	- 建议 citekey 风格：auth.lower + shorttitle + year
- Better Notes
	- 加强 Zotero 内部笔记
	- 导出 Markdown
	- 管理标注和笔记关系
- Actions and Tags for zotero
	- 可以设置简单的自动化工作流，比如给新文献打上指定标签


不过，在我们的工作流里，最重要的笔记应该管理在obsidian的笔记文件夹里，所以Better Notes也可以不安装。


# 文献文件夹

其实就是如何在zotero里组织文献，我们总不能全部丢在一起，一点分类也没有吧。

## 两种组织方式

Zotero 里有两个主要组织工具。一个是collection，文献的集合，它不是物理意义上的文件夹，只是将部分item链接到一起方便查看，不会物理复制一份，类似音乐软件的播放列表；一个是tags，方便检索

可以考虑使用类似下面的collection结构，**文献要按研究方向分类整理**。几个研究方向、一个Datasets（研究资源）、一个Projects 是个人工作流。00_Inbox 是暂存区。

```
My Library
├── 00_Inbox
|
├── Research_Topic_1
│   ├── 00_To_Read
│   ├── 10_Core
│   ├── 20_Retrieval
│   ├── 30_Reranking
│   ├── 40_Evaluation
│   └── 90_Surveys
│
├── Research_Topic_2
│   ├── 00_To_Read
│   ├── 10_Core
│   ├── 20_Prompting
│   ├── 30_Position_Bias
│   └── 90_Surveys
│
├── Datasets
│   ├── QA
│   ├── Long-context
│   └── Retrieval
│
└── Projects
    ├── Thesis_A
    └── Course_Project_B
```

使用前缀的tags结构，tags可以管理阅读状态、论文的重要性、论文涉及的方法等等。下面的六种标签应该够用了。注意，**只有当你预计未来会用它来筛选论文时，才创建这个标签**， 否则就会变成“为了分类而分类”。

```
status/     阅读状态
workflow/   处理状态  
role/       论文在知识体系或项目中的作用  
method/     技术方法  
dataset/    数据集 / benchmark  
project/    项目归属
```

```
status/inbox
status/to-read
status/skimmed
status/read

workflow/annotated
workflow/extracted
workflow/note-done
workflow/cited

role/core
role/background
role/baseline
role/related
role/negative-result
role/survey

method/dense-retrieval
method/sparse-retrieval
method/hybrid-retrieval
method/reranking
method/query-rewriting
method/long-context
method/context-compression
method/position-bias
method/chain-of-thought

dataset/nq
dataset/hotpotqa
dataset/ms-marco
dataset/longbench

project/thesis-a
project/course-rag
```

建议要约束标签数量，比如每篇论文最多打这些标签：

```
1 个 status/  
0-3 个 workflow/  
1-2 个 role/  
1-4 个 method/  
0-3 个 dataset/  
0-2 个 project/
```


## 使用方法

### 添加collection：左侧面板

Zotero 左侧栏的 **My Library** 包含库里的所有条目，在左侧栏右键 **My Library**，或点左上方的 **New Collection** 按钮来新建 collection；要建子 collection，就右键已有 collection 选 **New Subcollection**，或把一个 collection 拖进另一个 collection

collection 会按字母顺序排序，所以 `00_`、`10_`、`20_` 这种编号前缀是有用的

将论文加入collection中：
 - 已有论文：在中间论文列表里选中一篇或多篇，直接拖到左侧 collection，比如拖到 `RAG/20_Retrieval`。默认情况下，这只是把条目加入新 collection，不会从原来的位置移走。
- 新论文：用浏览器 Zotero Connector 保存时，Zotero 会保存到当前选中的 collection；保存弹窗里也可以改保存到哪个 collection

可以考虑：

```
刚保存的论文 → 00_Inbox
确定主题后 → 拖到 RAG / Long Context / Datasets / Projects 下的具体 collection
```

### 添加 tags：右侧面板

选中中间列表里的论文，然后看右侧面板，点 **Tags** 标签页，点 **Add**，输入：

status/inbox  
role/core  
method/reranking  
dataset/msmarco  
project/thesis-a

输完按 Enter/Return。也可以一次添加多个 tag：在 Tags 里点 Add 后，用 Shift+Enter/Return 输入多行 tag，再 Shift+Enter/Return 提交。

Zotero 的 tag 不是层级树，`status/read` 这种只是一个 tag 名字；但用 `/` 前缀能让你自己看起来像分组，也方便搜索和过滤。Zotero 官方文档说 tag 是用户命名的，一个条目可以有任意多个 tag

注意关闭自动tag，否则会很乱

### 用 tags 筛选：左侧面板

左侧栏底部有 **Tag Selector**，也就是 tag 选择器。点某个 tag，比如 `status/to-read`，中间列表就只显示带这个 tag 的论文；点多个 tag，会显示同时满足这些 tag 的论文，比如：

status/to-read + method/reranking

就能看到“待读 + reranking 方法”的论文。tag 选择器底部还有搜索框，可以输入 `method/` 或 `longbench` 找 tag。

批量加 tag 也可以在这里做：先在中间列表多选论文，然后拖到左下角某个 tag 上，Zotero 会给这些条目批量添加该 tag。

## 工作流

### 第一步：收文献

保存论文到：00_Inbox，同时加上tag：status/inbox

### 第二步：每周清理 Inbox

打开 `00_Inbox`，逐篇判断：

```
不相关 → 删除或保留但不进入项目 collection  
值得以后读 → 加 status/to-read  
核心论文 → 加 role/core  
综述 → 加 role/survey  
某项目会用 → 加 project/thesis-a
```

然后把它拖进对应 collection，例如：

```
RAG/20_Retrieval  
RAG/30_Reranking  
Long Context/30_Position_Bias  
Datasets/Long-context
```

这时建议移除旧状态 tag，比如把 `status/inbox` 改成 `status/to-read`。一个条目最好只保留一个 `status/...`，否则以后筛选会乱。

### 第三步：读完后更新状态

读完后在右侧 Tags 里把状态改成：

```
status/skimmed       # 粗读  
status/read          # 认真读  
status/annotated     # PDF 已标注  
status/extracted     # 标注已转成笔记  
status/note-done     # Obsidian literature note 完成  
status/cited         # 已在论文/项目中引用

```

这个流程的好处是：collection 表示“它属于哪个主题/项目”，tag 表示“它现在是什么状态、扮演什么角色、用了什么方法”。

## 00_Inbox/：临时入口

这里放还没想清楚的东西，比如：

```text
刚想到的研究问题
临时摘录
别人推荐的一篇文献
会议时记下的灵感
还没整理的 AI 输出
```

它的作用是降低记录成本。看到一个东西时，不应该先思考“它到底属于哪个文件夹”，而是先扔进 Inbox。但是 Inbox 不能长期堆积。每周要清一次。

## 10_Literature/Papers/：单篇文献笔记

这里放每篇文献对应的一篇 Markdown，笔记的名称与文献对应，通过每篇文献的元数据来检索。

例如：
```text
10_Literature/Papers/
├── @liRemoteSensingFoundation2024.md
├── @wangGeoVLM2025.md
└── @zhangOrientedObjectDetection2023.md
```

每篇笔记应当精简，最好用一段话而不是一篇文章，回答清楚几个问题就可以：

```text
这篇文章做了什么？
它解决什么问题？
它的方法是什么？
实验是否可信？
它和我的方向有什么关系？
```

注意不要按领域分文件夹，统一放在文件夹下即可，因为一篇文献可能同时属于很多领域，比如一篇遥感 VLM 论文同时属于遥感、CV、视觉语言模型等。


## 20_Field_Maps/：领域地图

这里放大方向的地图，每个大方向一个md文件，例如：

```text
20_Field_Maps/
├── Computer Vision 地图.md
├── Remote Sensing 地图.md
├── CV × Remote Sensing 地图.md
```

它回答：

```text
这个领域大概有哪些分支？
我目前知道哪些任务？
有哪些重要方法？
有哪些重要数据集？
有哪些代表性综述？
我对哪些方向感兴趣？
```

同时，这部分笔记还是一个索引，用于将领域基础概念链接到其他更详细的笔记和案例。可以写得全面，提到丰富的概念，但不需要深入解释知识。只需要尽量让一个不了解这个领域的人可以快速获取基础知识（名词），而更深入的了解有赖于链接的其他笔记


举例：

```markdown
# CV × Remote Sensing 地图

## 我当前的理解

## 主要任务

### 目标检测

代表问题：……

相关笔记：
- [[遥感目标检测中的小目标问题]]

### 语义分割

代表问题：……

相关笔记：
- [[LoveDA]]

### 基础模型

代表问题：……

相关笔记：
- [[遥感基础模型是否需要专门预训练]]
```



## 21_Question_Maps/：问题地图

按问题命名，一个问题一篇md文章，不必切分领域，领域太大了。

```text
21_Question_Maps/
├── 遥感基础模型是否需要专门预训练.md
├── 遥感 VLM 到底评估什么.md
├── 遥感目标检测的小目标问题为什么困难.md
├── 多光谱信息相比 RGB 有什么价值.md
├── 遥感模型跨区域泛化为什么困难.md
└── 遥感 benchmark 是否高估模型能力.md
```

Question map 的结构可以是：

```markdown

## 这个问题为什么重要？

## 当前我看到的主要观点

## 我当前的判断

## 可能的研究切入点

## 待读文献

```


## 30_Methods/：方法笔记

这里放方法概念，该领域常用的一些基础技术，往大了说，是把多篇论文中的共同方法抽出来理解。这部分更类似上课/教材讲的通用而基础的知识，以CV为例：

```text
30_Methods/
├── Vision Transformer.md
├── Masked Image Modeling.md
├── Contrastive Learning.md
├── Object Detection.md
├── Oriented Bounding Box Detection.md
├── Semantic Segmentation.md
├── Vision-Language Model.md
├── Adapter Tuning.md
└── Domain Adaptation.md
```

方法笔记回答：

```text
这个方法是什么？
它通常解决什么问题？
```

# Obsidian的配置

## 插件

为了适配这套工作流，obsidian里需要安装一些插件。

1. **Zotero Integration**

从 Zotero 插入引用、导入文献信息（citations、bibliographies）等、导入 notes 和 PDF annotations，依赖于 Zotero的插件Better BibTeX

该插件的具体配置方法如下：
- 确保 Zotero 里安装了 Better BibTeX
- 创建模板
	- 准备几个模板文件，里面写好模板的内容和需要导入的部分（本项目已经准备好）
	- 在 设置-插件-Zotero Integration 里，找到`import formats`，新建，选择导入模板。有几个模板就新建几个新的，可以自己命名每个模板对应的formats
	- 注意要修改 formats 的output path，本项目里为`10_Literature/Papers/{{citekey}}.md` 或 `10_Literature/Books/{{citekey}}.md` 或 `10_Literature/Surveys/{{citekey}}.md`，主要看选择的是哪一类文献的模板
- 使用模板：
	- 按住Ctrl+P，调出命令工具，输入`Zotero Integration: 模板名称`，在Zotero打开的情况下，会自动跳转到zotero，选择要导入的文献，就会自动创建文件，并填写模板中的字段

2. **Templater 或 Obsidian Templates**

生成文献笔记模板，比官方自带的要好用。

3. **Dataview**

把Obsidian vault 当成一个可查询数据库。它会读取 Markdown 文件里的 frontmatter / YAML 和 inline fields，我们可以用查询语句生成表格、列表、任务列表等。我们可以为文献建立yaml说明，再配合这个插件实现检索————注意**核心是yaml字段，dataview插件只是检索的手段**，现在obsidian原生的Obsidian Bases也可以做到类似的事情

譬如，写如下几行就能筛选出所有未精读的文献(to_read)，返回一个表格

```dataview
TABLE
  citekey AS "Citekey",
  relevance AS "Relevance",
  domain AS "Domain",
  task AS "Task"
FROM "10_Literature"
WHERE type = "literature"
WHERE status = "skimmed" OR status = "to_read"
SORT relevance DESC
```


## 文献的yaml标签

Obsidian 的 Properties 本质上就是文件开头的 YAML frontmatter。官方说明里，Properties 会以 YAML 格式存储在文件顶部，并且用 --- 包住

因此，为了方便检索，在读完一篇文献，为其做了笔记时，应当在开头添加yaml，形成类似的结构
```
@citekey.md
├── YAML / Properties 区域
└── Markdown 正文区域
```

Zotero Integration可以帮我们导入 citekey、title、authors、year、abstract、annotations，但**核心分类字段还是要自己维护**，比如domain / task / method_family / questions / relevance / projects


```yaml
---
type: literature
subtype: paper

citekey: wangRemoteSensingFoundation2024
title: "Remote Sensing Foundation Models"
year: 2024
authors:
  - Wang

domain:
  - computer_vision
  - remote_sensing

task:
  - foundation_model
  - representation_learning

method_family:
  - self_supervised_learning
  - masked_image_modeling

dataset:
  - unknown

status: skimmed
reading_level: L2
relevance: medium

projects: []

questions:
  - "遥感基础模型和自然图像基础模型的差异在哪里？"
  - "遥感数据的预训练任务应该如何设计？"

created: 2026-04-25
updated: 2026-04-25
---
```

也就是说
1. 每篇文献一篇 @citekey.md
2. 每篇文献必须有 YAML
3. YAML 字段只放稳定、可筛选的信息
4. 复杂理解写在正文
5. Zotero 插件只负责导入 metadata / annotations
6. domain / task / method_family 等知识分类由我们自己维护
7. Dataview 或 Bases 负责生成动态文献表
8. 20_Maps 里的人工总结永远比自动表格更重要


# 文献的分级

可以分成四个等级

```
L0：只在 Zotero 标 x_irrelevant，不进 Obsidian
L1：只在 Zotero 标 to_check，通常不进 Obsidian
L2：进 Obsidian，用 literature-note-L2.md
L3：精读，用 literature-note-L3.md
L4：深读/复现/批判，用 literature-note-L4.md
```

## L0：丢弃文献

标题相关，但摘要读完发现不相关的文献，比如方法、对象、数据集和研究的问题无关，或者质量明显不行。

处理方式：直接在zotero里tag标注x_irrelevant，不加入工作流


## L1：收藏但不读

看起来可能有用，以后写related work可能会查的文献

处理方式：Zotero的tag设置为to_check，可以加入对应方向的zotero collection里，无须做笔记。

## L2：泛读，极简笔记

新方向迅速扫文献、找综述材料时可以这样做；在寻找baseline工作时也可以，总之是在筛选文献

处理方式：读摘要和结论，加入工作流，但Obsidian 笔记只写 4 行：

```markdown
- Problem:
- Method:
- Relevance: strong / medium / weak
- Keep because:
```

例子：

```markdown
- Problem: 研究长上下文模型在多文档问答中的事实保持问题。
- Method: 对比 dense retrieval、long-context LLM、hybrid retrieval 的 answer faithfulness。
- Relevance: strong
- Keep because: 可能支撑我论文中“长上下文不等于可靠引用”的论点。
```

## L3：精读，理解方法和实验

筛选标准：
* 和你方向高度相关；
* 未来可能引用；
* 是重要 baseline；
* 方法和自己想法类似
* 数据集、指标、实验设计值得参考

要问作者的研究对我的研究有什么用


## L4：深读，可复现/可批判/可写进 related work

适合：
* 你论文方法直接依赖；
* 领域公认经典；
* 所有相关工作都会引用；
* 审稿人很可能问；
* 需要复现实验或改进它。

直接服务论文写作才需要进入这一步，否则就浪费精力了。


## 复习与回顾

回顾的是L3/L4文献，可以考虑在笔记底部补充内容，让自己能回答其中的核心问题，复习只需要做到能回答这些即可

```
- 这篇文章的核心创新是什么？
- 它最强的实验是什么？
- 它最弱的假设是什么？
- 它和我的方法最大差异是什么？
- 如果审稿人提到它，我怎么回应？
```
